# ESP32-S3-CAM Agent Development Contract

本文件是 `E:\MyProjects\DeskFriend\ESP32\ESP32-SPEC` 下的 agent 开发入口。任何修改 `ESP32-S3-Dual` 的 agent 在编码前必须阅读本文件和 `ESP32-S3-FREERTOS-SPEC.md`。

## 强制规则

1. 先检查当前工程的 `platformio.ini`、任务头文件和相关参考资料；不要凭默认 ESP32 引脚或默认板卡配置开发。
2. 所有硬件引脚只能在集中配置处定义。当前已确认的 Goouuu ESP32-S3-CAM 相机引脚见主规范第 4 节，舵机和 NeoPixel 引脚见第 5 节。
3. FreeRTOS 任务必须有明确的任务名、栈大小、优先级、核心亲和性、周期/阻塞策略和停止/错误行为。禁止在任务循环中忙等。
4. 任务之间不得直接操作另一个任务的私有外设状态。跨任务数据使用消息队列、任务通知、事件组或受保护的共享状态；共享 `volatile` 变量必须说明原子性和一致性边界。
5. 相机帧的所有权必须明确：取得 `camera_fb_t*` 后，无论成功还是失败路径都必须调用 `esp_camera_fb_return()`；编码产生的堆内存必须由拥有者释放。
6. 不得在 Wi-Fi、相机采集或 Web 请求任务中执行长时间无界阻塞；网络重连、客户端处理和帧处理必须可让出 CPU。
7. 任何新增库、分区表、Flash/PSRAM 模式或编译宏都必须同步更新 `platformio.ini` 和规范文档。
8. 不要把密码、令牌或真实设备凭据提交到仓库。使用宏、未跟踪配置文件或运行时配网。
9. 修改硬件配置后必须完成 `pio run`；涉及运行时行为时还要用 115200 串口日志和实际设备验证。
10. 完成任务时必须在变更说明中列出：修改的任务、资源/栈影响、引脚影响、验证命令和未验证风险。

## 开发顺序

1. 阅读主规范并确认需求属于任务、硬件、网络、Web 或构建配置哪一层。
2. 设计任务边界和数据通道，再修改代码。
3. 编译并检查栈水位、堆/PSRAM、Wi-Fi 和外设初始化日志。
4. 若引脚、时钟、帧格式或内存模型发生变化，更新主规范的“当前状态”和“变更记录”。

规范正文：`ESP32-S3-FREERTOS-SPEC.md`
